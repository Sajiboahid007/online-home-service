## 3. Critical Security Findings

### 3.1 Simulated OTP & Client-Side Auth Bypass (Critical)
- **Files:** [login.component.ts](file:///C:/unversity/online-home-service/src/app/features/auth/login/login.component.ts#L635-L794), [auth.service.ts](file:///C:/unversity/online-home-service/src/app/core/services/auth.service.ts#L68-L151)
- **Details:**
  - `sendOtp()` simulates SMS dispatch via `setTimeout`, and `verifyOtp()` accepts **any 6-digit string** without validating an OTP or creating a `FirebaseAuth` session (`firebaseService.auth`).
  - Logging in with an admin phone number (e.g., `01700000001`) or editing `localStorage` (`kajkhoj_user`) grants `superadmin`, `admin`, or `worker` UI access through client-side route guards.
  - Because `FirebaseAuth` is never signed in, `request.auth` evaluates to `null` for live Firestore, Realtime Database, and Storage rules.

### 3.2 Unauthenticated Callable Cloud Functions & Unverified Webhook (Critical)
- **Files:** [dispatch.ts](file:///C:/unversity/online-home-service/functions/src/dispatch.ts), [payments.ts](file:///C:/unversity/online-home-service/functions/src/payments.ts), [reviews.ts](file:///C:/unversity/online-home-service/functions/src/reviews.ts), [safety.ts](file:///C:/unversity/online-home-service/functions/src/safety.ts)
- **Details:**
  - Every `functions.https.onCall` handler (`acceptJob`, `grabBoardJob`, `submitBid`, `chooseBid`, `updateJobStatus`, `completeJob`, `cancelJob`, `requestWithdraw`, `submitReview`, `banUser`, `unbanUser`, `triggerSOS`, `approveWorker`, `rejectWorker`) lacks `context.auth` and `context.auth.token.role` / ownership verification.
  - `banUser` and `unbanUser` in [reviews.ts](file:///C:/unversity/online-home-service/functions/src/reviews.ts#L118-L160) call `admin.auth().setCustomUserClaims(uid, { banned: true/false })`, which overwrites all other custom claims (such as `role`).
  - `paymentWebhook` in [payments.ts](file:///C:/unversity/online-home-service/functions/src/payments.ts#L9-L49) trusts `req.body` (`status === 'VALID' || 'VALIDATED'`) without verifying SSLCommerz/bKash signatures, secrets, or server-side transaction validation APIs.

### 3.3 Overly Permissive Firebase Rules (High)
- **Firestore ([firestore.rules](file:///C:/unversity/online-home-service/firestore.rules)):**
  - `jobs/{jobId}` `allow update` (lines 47–48) allows customers or workers to modify any job field (`finalPrice`, `paymentStatus`, `status`, `commission`, `startOtp`).
  - `jobs/{jobId}/messages/{msgId}` (lines 63–66) and `reviews/{id}` (lines 70–73) allow any signed-in user to read/write any job's chat messages or overwrite/delete any review.
  - `workers/{uid}` `allow create` (line 25) allows setting privileged fields (`verified`, `walletBalance`, `isPremium`, `rating`) on document creation.
  - `jobs/{jobId}/offers/{workerId}` (line 53) allows `isOwner(workerId)` to write offer documents directly.
- **Realtime Database ([database.rules.json](file:///C:/unversity/online-home-service/database.rules.json#L10-L15)):**
  - `jobTracking/$jobId` allows any authenticated user to `.read` and `.write` any job's tracking state.
- **Cloud Storage ([storage.rules](file:///C:/unversity/online-home-service/storage.rules#L20-L24)):**
  - `/jobs/{jobId}/{allPaths=**}` allows any signed-in user to read and overwrite any job's photos.

## 4. Bugs & Frontend / Backend Mismatches

1. **Frontend vs. Cloud Functions Schema Mismatches**
   - `onJobCreated` ([dispatch.ts](file:///C:/unversity/online-home-service/functions/src/dispatch.ts#L33-L80)) checks `jobData.status === 'requested'`, `jobData.customerLocation`, `worker.category == jobData.category`, `worker.status === 'approved'`, `worker.currentJobId`, and root `geohash`. In contrast, the frontend models and [firestore.rules](file:///C:/unversity/online-home-service/firestore.rules#L45) use `status: 'pending' | 'searching'`, `location`, `categoryId` / `categoryIds[]`, `verificationStatus`, `isBusy`, and `homeLocation.geohash`.
   - `updateJobStatus` ([dispatch.ts](file:///C:/unversity/online-home-service/functions/src/dispatch.ts#L308)) checks `job.startOTP`, whereas the frontend writes `startOtp`.
   - `completeJob` ([dispatch.ts](file:///C:/unversity/online-home-service/functions/src/dispatch.ts#L357-L363)) and `requestWithdraw` ([payments.ts](file:///C:/unversity/online-home-service/functions/src/payments.ts#L68-L76)) reference nested `wallet.commissionDue`, `wallet.balance`, `wallet.totalEarnings`, and `metrics.completedJobs`, whereas `WorkerProfile` uses flat `commissionDue`, `walletBalance`, and `totalJobs`.

2. **Missing Composite Indexes**
   - [firestore.indexes.json](file:///C:/unversity/online-home-service/firestore.indexes.json) is missing indexes for `workers` (`isOnline` + `category` + `geohash`) used by `onJobCreated`, and (`isOnline` + `lastHeartbeat`) used by `autoOfflineStaleWorkers` ([schedulers.ts](file:///C:/unversity/online-home-service/functions/src/schedulers.ts#L15-L18)).

3. **Worker Onboarding Direct Firestore Writes**
   - [register-worker.component.ts](file:///C:/unversity/online-home-service/src/app/features/auth/register-worker/register-worker.component.ts#L306-L386) generates `worker_onboard_<timestamp>` and writes `role: 'worker'` to `users/{uid}` without Firebase Auth, which conflicts with `isOwner(uid)` and `request.resource.data.role == 'customer'` in [firestore.rules](file:///C:/unversity/online-home-service/firestore.rules#L14-L15).

4. **Static / Local-Only Live Trip Sharing**
   - [share-trip.component.ts](file:///C:/unversity/online-home-service/src/app/features/share-trip/share-trip.component.ts#L29-L56) reads only from local `JobService` and calculates a static worker coordinate offset (`lat + 0.008, lng - 0.006`) rather than subscribing to RTDB `jobTracking/{jobId}`.

5. **Unit Test Provider Gap**
   - [app.spec.ts](file:///C:/unversity/online-home-service/src/app/app.spec.ts) needs `ConfirmationService` in `TestBed` providers to pass.

## 6. Production Pre-Deployment Checklist

1. **Authentication:** Enable real Firebase Phone Auth (`signInWithPhoneNumber`) and remove demo/simulated OTP bypasses from production builds; preserve existing custom claims when updating `banned` status.
2. **Cloud Functions Security:** Enforce `context.auth` + role/participant checks in all `onCall` functions and verify gateway signatures/validation APIs in `paymentWebhook`.
3. **Schema & Indexes:** Align field names (`startOtp`, `categoryIds`, `verificationStatus`, `walletBalance`, `commissionDue`, `totalJobs`, `homeLocation.geohash`) between Angular models and Cloud Functions, and add missing composite indexes to `firestore.indexes.json`.
4. **Security Rules:** Restrict `jobs` updates, `messages`, `reviews`, `offers`, `workers` creation fields, RTDB `jobTracking`, and Storage `/jobs/**` paths to authorized job participants and admins.
5. **Testing:** Provide `ConfirmationService` in [app.spec.ts](file:///C:/unversity/online-home-service/src/app/app.spec.ts) and run the full test suite before deploying.
